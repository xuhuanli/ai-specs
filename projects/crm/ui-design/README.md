# CRM 全应用交互设计

第一版本地提交：`1021a01`。当前版本保存为 V2 阶段快照，仍有较多页面与实际展示不一致，不作为已完成全量对齐的设计基线。后续按用户指定的模块和开发进度逐步同步修订。

本轮优先级：**实机实际展示 > Figma 同一页面最后一版 > 当前 iOS 代码条件**。同一版的正常、空态、处理中、结束等状态保留，不把最后一张空态图误当成唯一常态。

直接用 Chrome 或 Safari 打开 [index.html](index.html)，无需安装依赖、构建工程或连接业务服务。所有页面在同一个 HTML 应用中，通过地址末尾的 `#页面ID` 切换，便于保留交互状态与跨页连线。

本版按 2026-11-06 核对的 iOS `develop / 221c9898` 组织，参考 Android `develop / b98e308` 补充理解，共整理 **153 个页面或明确状态、14 个业务模块**。共用筛选、选择器、确认弹窗和图片预览不另计页面数。完整清单及代码定位见[页面覆盖与来源](references/页面覆盖与来源.md)。

- 已查看连接的 iPhone 16 Pro Max（CRM 3.0.0）中的首页、医生列表、工作台、应用、我的、今日开方订单、工单列表、分组类型选择及工单处理记录／明细、发起协同基础模板。实际只读观察，不提交业务操作。
- 修正首页去除多余导航标题、搜索与统计表；医生卡片改平铺布局并按生命周期隐藏经营信息；工作台改四列宫格、待办卡片；订单卡片按当前 `OrderListCell` 字段顺序；工单改双页签、白底消息及结束态。
- 右侧新增“后台条件与页面状态”，整理137条源码条件、373个条件选项。选择后可观察已接入的组件、标题、字段、列表项与操作变化；紫色“条件”按钮可查看字段判断及源码位置。
- “状态总览”集中列出条件选项，可直接跳入某个展示分支；“显示／隐藏条件标注”可切换注释层。手机窄屏可通过“设计面板”打开目录与条件选择器。
- 每个页面标记实机核对状态，见[逐页覆盖表](references/页面覆盖与来源.md)。未逐页核验的页面保留“尚未逐页实机核验”，不能把页面能打开等同于已全部对齐。
- 条件记录用于补齐UI观察不到的分支，包含后台字段、角色、入口参数和派生状态；不是已穷尽全部接口／权限规则，也不表示373种场景均已在设备上出现并核实。

## 怎么浏览

- 左侧按模块查看页面，也可搜索页面名、业务或操作；`⌘ K`／`Ctrl K` 聚焦搜索。
- 中间为可操作的手机预览；可以使用底部五个入口，也可按实际流程进入下级页面、返回。
- 右侧显示本页交互提示、相关页面、源码位置和已查看的 Figma 参考。
- “页面总览”查看全部模块及页面；“专注预览”按100%尺寸查看；手机画框平时保留宽高比例并缩放适应窗口；支持 390／430／实机 440 三种手机宽度。
- 顶部可切换普通医助／管理人员及列表的正常、空数据、加载、失败状态。工单模块还可在右侧切换发起人／跟进人／负责人演示视角。
- 表单、领取、关注、拜访、工单消息等保存在当前浏览器本地。“重置演示”恢复初始内容。刷新可保留已保存状态；浏览器限制本地文件存储时仍可在当前打开期间演示。
- 手机浏览器打开时直接显示应用视图，隐藏桌面的目录和说明面板。

## 建议体验的流程

1. 医生 → 搜索／新增医生 → 医院与科室选择 → 医生主页 → 资料／标记／潜力／账户。
2. 工作台 → 创建日程或添加拜访 → 必填校验 → 保存 → 日历或拜访记录回看。
3. 应用 → 订单查询 → 筛选／搜索 → 订单详情 → 关注、地址、开票、退款、售后、物流与溯源。
4. 协同工单 → 创建 → 聊天式详情 → 发送文字／演示附件 → 退回／转派／回复与下一步 → 完成评价。
5. 奖励池 → 确认领取 → 兑换卡数量变化 → 领取记录；医生账户 → 单券选择 → 确认赠送。
6. 运营活动、团队数据、流失预警、PK、患者感谢、特殊审批及业务资料各自分组浏览。

上传图片支持选择本机图片，也可点击“使用演示图片”，无需准备真实资质或业务图片。图片只保存在本地原型中，不上传。

## 设计依据和覆盖边界

这是一份**基于现有实现重建的交互设计**，不宣称所有页面均已取得真机截图或按设计稿逐像素复刻。布局首先服从已看到的实际展示，未看到时按 iOS 的当前入口、View／Cell／XIB 与字段补齐；使用了 54 个 iOS 仓库中的静态图标资源，来源在 [assets/manifest.json](assets/manifest.json)。Android 仅用于补充字段与流程理解，平台冲突沿用本次用户指定的 iOS 优先原则。

已保留的重要边界：

- 当前 iOS 工单列表进入聊天式详情；旧资料详情作为相关入口保留。
- 新版“咨询订单”列表整行无独立订单详情跳转，头像可进入医生主页；“问诊订单”另有详情及聊天链路。
- 工单类型按实机的分组选择弹层组织；固定的分类与名称不可编辑。当前实机基础模板没有附加关联订单／医生／电话，额外单选、多选、数字、文本与同步字段只在明确标注的动态模板示例中出现，未覆盖全部真实模板。
- 运营活动展示预算概览、规则、记录与医生表格，没有新增未经确认的预算申报流程。
- 运营有道仅有外部小程序入口及返回；未取得的小程序内部页面不虚构。
- 地图、图片识别、短信、钉钉、推送、拨号、支付／退款、审核、领取与文件生成均为本地演示，不调用实际服务。
- 新版券和慧眼寻医以 iOS 当前主线为依据；Android 对应功能分支是否集成仍沿用接手指南中的待确认状态。
- 管理人员和工单身份用于演示入口关系，不代替真实服务端权限。不同账号、业务状态和接口字段的全部组合尚未实机验证。

## 文件结构

```text
ui-design/
├── index.html                  打开入口
├── styles.css                  工作台与手机页面样式
├── catalog.js                  模块、页面及依据登记
├── conditions.js               源码条件及变体登记
├── alignment.js                实机布局修订与条件展示绑定
├── app.js                      页面、演示数据和交互逻辑
├── 打开预览.command             可选：用本机静态服务器预览
├── assets/                     iOS 图标及资源来源
├── references/                 页面清单和覆盖来源
└── qa/                         本次原型验证记录
```

如浏览器限制本地文件，双击 `打开预览.command`。它仅在本机 `127.0.0.1:8768` 提供静态预览，并打开 `/ui-design/`；关闭终端或按 `Ctrl C` 即可停止。此方式以 CRM 目录为静态根，便于查看代码依据链接；不对局域网开放。
