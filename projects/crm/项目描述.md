## 4. 技术结构与现有规范

### iOS

主工程为 `GCCRM`，通过 `GCCRM.xcworkspace` 打开，依赖由 CocoaPods 管理。以 Objective-C 为主，新增模块逐步加入 Swift，界面使用 UIKit，整体偏 MVC。

`GCCRM/ViewController/` 按业务划分页面；控制器协调生命周期、请求和跳转，View/Cell 负责展示与交互回调，Model 承载数据，RequestAPI 描述接口。历史 `ViewModel/` 目录主要存放 View、Cell 等 UI 组件，不代表严格的 MVVM 架构。

网络存在两条主要路径：老 CRM 接口使用 YTKNetwork 和 `GCRequestManager`／`GCAPIRequestManager`；GAPI 接口使用 `CRMNetRequest` 与 KMM 网络库。修改功能前需要沿目标模块实际调用链确认所用入口。当前代码在模拟器下对 `CRMNetRequest` 请求及上传直接返回不支持，不能用模拟器构建通过代替真实网络验证。

| --- | --- |
| Bundle ID | `com.gancaoCrm.crm` |
| Swift 工程语言配置 | `SWIFT_VERSION = 4.2` |
| 主 Target 最低部署版本 | Debug、Release 均为 iOS 13.0 |
| 工程版本 | `MARKETING_VERSION = 3.0.0`、`CURRENT_PROJECT_VERSION = 1`；不是已发布版本认定 |

现有 README 已包含 MVC 职责、目录落位、ObjC／Swift 风格、混编、网络、缓存、类型转换、UI 复用及开发检查要求，优先作为本端规范来源，不另复制一套云诊室代码规则。

### Android

以 Kotlin 为主，界面使用 XML 和传统 Android View，采用 MVVM + Repository。典型调用链为 Fragment／Activity → ViewModel → Repository → ApiService，页面观察 LiveData 更新界面，依赖注入使用 Dagger 2。

主业务位于 `app/src/main/java/com/igancao/crm/`：`ui/` 按业务拆包，`base/` 提供页面和列表基类，`api/` 定义接口，`bean/` 保存模型，`di/` 管理依赖注入，`util/`、`widget/` 提供公共能力。另有 `UnAppModule` UniApp 扩展模块和 `screenadapter` 屏幕适配模块。

主接口使用 Retrofit／OkHttp 与协程；GAPI 网关另有 Fuel 路径。新增功能应沿用当前模块的请求、状态处理和登录失效逻辑。
