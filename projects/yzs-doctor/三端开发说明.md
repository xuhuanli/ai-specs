# 云诊室医生端三端开发说明

三端在产品需求确认阶段统一业务流程、业务规则、状态含义和业务验收口径；工程架构、代码组织、UI 技术、分支和提交分别遵循各端约定。本说明提供目录定位与规范索引，便于后续按需求进入对应项目。

技术与 Git 快照的核对日期为 2026 年 10 月 20 日；2026 年 11 月 2 日仅调整目录入口与链接，未重新验证以下技术快照。以下目录、配置和 Git 信息来自原核对时的本地检出；原核对未拉取远端更新，未安装依赖、构建、运行测试或操作设备。当前业务实现是否一致，需在具体需求下分别追踪调用链。

### 开发要点

- 主 App 通过 workspace 打开；依赖使用 CocoaPods。当前 Podfile 的 iOS 基线为 13.0；主 App 工程配置对应 13.0，Widget 配置为 17，具体 Target 分别看工程配置。

- Objective-C 布局使用 Masonry，Swift 布局使用 SnapKit；优先复用 HPT 颜色、字体和组件，保持相邻代码风格。
- Objective-C 格式使用项目 `.clang-format`，4 空格缩进、不使用 tab，配置行宽为 120。类前缀、VC、Model、View 命名依照现有模块约定。
- 新页面、业务 View、Model 和 API 放在规范指定的对应目录。VC 管理页面生命周期与交互，复杂业务沿用现有 Manager、Tool 或 ViewModel。
- 网络栈并存。修改前确认目标模块实际使用的框架、请求基类、域名切换、登录失效及回调约定，保留缓存、埋点、兜底和兼容行为。
- Model 字段、接口参数、缓存键、通知、URL Scheme 和埋点属于兼容边界；开方、支付、登录等改动需沿完整链路判断影响。
- block、通知、异步请求和 Swift 与 Objective-C 互操作需遵循现有生命周期处理；不以同步开发为由迁移稳定模块或改写第三方生成内容。

### 开发要点

- 当前配置为 AGP 8.12.1、Gradle Wrapper 8.13、Kotlin 2.0.21；compileSdk 36、targetSdk 34、minSdk 24，Java 与 Kotlin 目标版本均为 17。这些为项目配置，不代表本机环境已安装或构建可用。
- UI 使用 XML 与 ViewBinding，架构为 View → ViewModel → Repository → ApiService 或 GapiService；复用 Hilt、LiveData 和既有基类。
- 页面优先复用 `BaseVMVBFragment`、`BaseListFragment`、`BaseActivity` 等。覆写初始化流程时保留规范要求的 `super` 调用，避免丢失 ViewModel 和基础观察者。
- 请求放入既有生命周期作用域；CI 接口用 `map`，GAPI 用 `gmap`，复用 loading、错误和登录失效处理，Repository 保持薄转发。
- Kotlin 字段和方法通常使用 camelCase；后端字段按实际协议映射，保留必要的关键字转义与历史 JSON 兼容。按 README 要求为 `bean/` 外的 `data class` 添加 `@Keep`。
- 复用共享颜色、尺寸和样式；新文案放 `strings.xml`。字重 500 优先使用项目的 `FontWeight500*` 控件或对应扩展，依照 UI 技能处理设计明确的例外。
- 异步回调检查页面和 binding 有效性；列表绑定重置全部可变状态，避免复用污染；网络和阻塞工作不放在主线程。
- 生命周期及 override 方法在前，自定义方法在后，按 private、protected、internal、public 排列；超过 3 个参数的调用优先使用命名参数。
- 格式化使用 Android Studio 的项目方案，Kotlin 官方风格、通常行宽 120，XML 续行缩进 4；不为统一样式而批量改写历史文件、Java 厂商模块或资源。
- 依赖在 `gradle/libs.versions.toml` 中维护；新增模块、三方库及版本变更分别遵循 README 的模块和依赖约定。

构建配置含 `debug`、`release`、`pre`。README 将它们分别描述为测试、线上及可调试线上接口的本地预发；具体任务与签名、环境以当前配置为准，本轮未执行任务枚举或构建。

### 开发要点

- 当前产品配置为兼容 SDK `5.0.4(16)`、目标 SDK `5.1.1(19)`，使用 ArkTS、ArkUI 和 Hvigor。工程存在 `package.json` 不代表采用 npm Web 构建流程。
- 模块内部按 `pages`、`view_models`、`components`、`models`、`api`、`state` 等职责组织；存在功能子包时沿其现有组织方式。
- 目录使用小写下划线；文件大写开头，无分隔符。目录已表达职责时文件名可不重复 Page、ViewModel 后缀，导出的类名按职责区分。
- 项目规范限制 ArkTS／TypeScript 单文件不超过 800 行、单文件夹不超过 8 个文件；新增及相关重构遵守限制，不机械整理无关存量。
- 使用明确类型，按本项目规范避免 `any`、对象展开、对象字面量类型、静态方法中的 `this` 和 `as number` 强转。
- 新页面、组件和相关重构采用 V2 状态管理，存量 V1 不强制迁移；根据是否需要独立状态、生命周期选择 `@Builder` 或 `@Component`。
- 全局用户状态复用 `biz_user` 的 UserState；页面和应用状态沿用现有 V1、V2 及 AppStorage 方案。API 复用 NetworkApi 与已有拦截器，注意请求生命周期和取消。
- 主路由注册入口为 `entry/src/main/ets/router/router.ets`；实际还有模块自己的路由文件。跨模块跳转复用 `biz_middle_extension` 等现有协议，不由目录名称推定完整跳转链。
- `emitter` 注册和取消配对，取消时传入同一个 callback。ArkUI 每个属性调用独占一行，复用项目资源和组件。
- AGENTS 规定新增网络地址统一到 `biz_common_reuse/src/main/ets/constant/Constant.ts`；构建脚本只在涉及其逻辑时修改。
- 仓库存在 `.codegraph/`；后续关系查询在工具可用且索引可信时优先使用，否则降级到 `rg` 与源码，不自行重建索引。

iOS 和 Android 的分支技能花名列表均为 `shengy`、`cil`、`xiatw`、`daogc`、`erlj`、`kongqc`、`chiyz`、`pipy`、`sans`、`songj`。实际生成或创建分支时，如未提供花名或不在列表内，按对应技能先确认。本次只梳理约定，不生成或切换开发分支。

提交前分别核对目标仓库的 status、diff 和暂存区，只添加本次任务相关文件；本地 commit、push、MR 和合并分别记录。根目录文档本地提交不授权对子仓库执行这些动作。
