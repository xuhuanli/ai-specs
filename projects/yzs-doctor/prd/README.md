# 云诊室医生端版本需求文档索引

版本资料先按版本归档，再按文档负责人分目录，完整路径为 `prd/prd-vxxx-YYYYMMDD/<姓名>/`。当前用户的目录名为 `sanshi`，默认使用 `prd/prd-vxxx-YYYYMMDD/sanshi/`，其中只维护本人负责需求产生的文档。

`xxx` 使用已确认的需求版本标识，日期取版本目录首次创建日。同一版本后续继续复用原目录，不因修改日期或负责人不同重新建版本目录。首次创建时登记版本入口；版本内的 README 索引各负责人目录，个人目录的文档索引维护本人负责的资料。

## 每个版本的资料

```text
prd/
├── README.md                     版本目录索引
└── prd-vxxx-YYYYMMDD/
    ├── README.md                 各负责人目录索引
    └── sanshi/                   sanshi 负责的需求与文档
        ├── 00-文档索引.md
        ├── 01-产品需求.md
        ├── 02-技术方案.md
        ├── 03-开发任务.md
        ├── 04-AI测试用例.md
        ├── 05-人工测试验收.md
        └── sources/              按需保存本次相关材料
```

其他负责人使用各自已确认的姓名目录，与 `sanshi/` 同级。模板按实际负责范围使用，不要求每人都有全部五类文档，也不自动生成同一版本的所有需求。

同一需求涉及多人时，各自维护本人负责的产品、开发或测试资料，通过文档链接、需求编号和已确认版本关联。引用其他人的资料时注明负责人目录，避免不同文档里的局部编号混淆；共用业务逻辑和验收要求保持一致，冲突先向用户确认。

姓名目录表示文档归属，产品、开发和测试的填写与确认职责仍按[模板使用说明](../../../docs/requirements/README.md)执行。本目录仅由工作区根文档仓库记录本地提交，不上传任何远程。
