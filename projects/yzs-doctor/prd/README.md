# 云诊室医生端版本需求文档索引

版本资料先按版本归档，再按负责人分目录，完整路径为 `prd/prd-vxxx-YYYYMMDD/<负责人>/`。负责人使用实际姓名或团队标识，不预设默认人员；同一人可在同一需求资料中维护多个适用端的方案、任务与验证结果。

`xxx` 使用已确认的需求版本标识，日期取版本目录首次创建日。同一版本后续继续复用原目录，不因修改日期或负责人不同重新建版本目录。首次创建时登记版本入口；版本内的 README 索引资料目录，目录内的文档索引维护对应需求资料。已有目录名、负责人和执行记录保留历史事实，不表示后续只能由原负责人开发。

## 版本目录

当前暂无版本需求资料。后续创建实际版本目录后，在此登记版本、创建日期和资料入口。

## 每个版本的资料

```text
prd/
├── README.md                     版本目录索引
└── prd-vxxx-YYYYMMDD/
    ├── README.md                 各负责人目录索引
    └── <负责人>/                本次需求与文档
        ├── 00-文档索引.md
        ├── 01-产品需求.md
        ├── 02-技术方案.md
        ├── 03-开发任务.md
        ├── 04-AI测试用例.md
        ├── 05-人工测试验收.md
        └── sources/              按需保存本次相关材料
```

新建资料时使用实际负责人的姓名或团队标识作为目录名；接手已有需求时沿用原文档位置并记录实际执行者。模板按本次需求范围使用，不要求每人都有全部五类文档，也不自动生成同一版本的所有需求。

同一人可以兼任需求整理、各端开发和测试职责，各类文档通过链接、需求编号和已确认版本关联。多人接续时记录各自实际负责范围，引用相关资料时注明归档目录；共用业务逻辑和验收要求保持一致，冲突先向用户确认。

负责人目录只用于归档，产品、开发和测试的填写与确认职责仍按[模板使用说明](../../../docs/requirements/README.md)执行，可由同一人兼任。本目录仅由工作区根文档仓库记录本地提交，不上传任何远程。
