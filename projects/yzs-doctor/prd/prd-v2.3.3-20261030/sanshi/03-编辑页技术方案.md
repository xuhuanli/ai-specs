文档版本 v2.3，2026-11-02。关联[产品需求 v2.0](01-产品需求.md)与[三端差异](02-编辑页现状与三端差异.md)。本方案已实施新建及四字段回填能力；列表已有文章临时测试入口现已移除，本轮已接入详情正式编辑入口。实际代码和必要适配见04，编译、主机回归、设备及测试环境草稿结果见05；未执行的真实发布和图片上传不标记为通过。

2026-11-02 本轮新增第9节医生主页和聊天入口方案，关联REQ-012至018／AC-014至020，已按SRC-020收敛完成接入并按功能提交，最终43项主机回归通过，用户已报告手动测试通过，本机CLI编译仍受SDK限制；此前编辑与详情接入记录保留历史状态。

本方案仅维护sanshi负责的编辑、详情接入、主页和聊天入口改动；详情基础保存／发送／微信分享及正文Web承载由同事维护，本文只保留调用依赖，不为其扩展新任务或认定个人需求遗漏。详情4项改动的范围对照见产品需求第3节。

## 1 推荐结论与适用边界

推荐 ArkUI 原生页面壳＋应用内置的 ArkWeb 图文编辑区。原生负责导航、保存弹框、拍照／相册工具栏、媒体选择、上传与后台请求；标题与正文位于同一份本地编辑文档内，支持整体滚动。正文以 HTML 为编辑和交换格式。

理由是两端已有文章正文均使用 HTML，最新 Figma 又包含段落、多张图片和标题滚出视野的长文状态。该组合能直接承接图文内容，不必先把已有 HTML 转成原生 span，再反向重建 HTML。编辑文件随应用打包，不需要单独部署编辑网站；上传与保存继续依赖现有后台。

粘贴范围已确认：保留文字、换行、段落及常见加粗、链接等基础格式，不增加格式工具栏。表格、视频、复杂 Word 排版和直接粘贴图片不纳入本期，Q-006 已关闭。除本轮新增详情编辑入口及保存返回衔接外，文库、转载和分享规则不变。

### 已有文章回填与临时入口

路由参数为title、content、doctor_article_id、system_article_id四个独立字段。临时测试时从MyArticles取当前条目的四字段，通过已有dynamicPageRegistry.pushAsync传入；该临时点击及仅用于测试的item传参分支现已移除，MyArticles恢复原有新建入口，不传参数。正式详情页本轮已按同一四字段协议接入。ArticleEdit.aboutToAppear读取hptRouter.params，由ViewModel只配置一次会话。ArticleEditorParams统一识别有效的正整数字符串ID，有任一有效ID即为已有文章；缺失或无效ID归为0，无有效ID时使用空白标题正文。

编辑器就绪后通过现有JSON参数桥一次传入标题与HTML。原文先放入惰性template，复用基础格式清理规则后再挂载；合法HTTP／HTTPS原文图片登记为可序列化图片，脚本、事件属性、嵌入页面及非法图片地址不进入编辑DOM。纯文本原文保留换行与特殊字符。标题回填保持原值，超30字的旧标题由既有提交校验提示处理，不因正文输入而截断标题。

初始化后保存实际标题和规范化HTML基线，快照额外报告hasChanges；焦点、选区和revision变化不算修改。已有文章按基线比较，新建仍按有效内容判断返回。重复页面就绪和普通前后台切换不重新回填。ArticleEditorApi使用当前会话保留的两个原ID，正文只取当前快照，不从列表摘要构造，也不按ID另发列表或详情请求。

临时列表点击事件原使用TODO(article-edit-test-entry)标记，测试后已移除该事件、对应注释及openPhoneEditor中仅被临时入口使用的item传参分支；当前列表已恢复详情跳转，正式详情编辑入口见下节。四字段接收、回填和保存能力继续保留；测试入口不代表正式允许所有来源文章手机编辑。

### 方案比较

| 方案 | 适配情况 | 当前判断 |
| --- | --- | --- |
| ArkUI 原生 RichEditor | 原生图文输入可行，项目聊天和快捷开方已有使用；HTML 导入导出还需处理支持标签、样式、图片来源与往返转换 | 可选，但现有文章 HTML 兼容成本较高，当前不优先 |
| 本地 ArkWeb＋受控 contenteditable | 直接编辑 HTML，可用一个文档承载标题与正文；需认真处理输入法、选区、粘贴、上传和键盘 | 当前推荐，范围与两端数据形式、最新 UI 较匹配 |
| 引入完整第三方编辑器 | 适合后续明确需要丰富排版命令的场景，但引入包、文档模型和 HTML 转换维护成本 | 当前需求尚未要求完整格式工具，不先增加此依赖 |
| 远程 H5 编辑页 | 需要 Web 发布、页面可用性与版本协同，当前没有指定远程编辑服务 | 不作为本轮基线 |

鸿蒙项目[构建配置](../../../repos/hos_doctor/build-profile.json5)当前最低 API 16、目标 API 19。官方文档说明 StyledString.fromHtml 的部分标签转换能力从 API 20 才支持；toHtml 也有明确可转换样式范围。因此不能把最新系统的转换支持直接当作最低支持设备上的完整 HTML 兼容能力。这是本方案优先本地 HTML 编辑的依据之一，而不是认定原生 RichEditor 无法做图文。[官方属性字符串文档](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/reference/apis-arkui/arkui-ts/ts-universal-styled-string.md#fromhtml)

## 2 工程组织与复用

业务代码放在 yzs_article 内，新增页面使用项目要求的 V2 状态管理。共享模块只补本页必要的路由标识和实际依赖，不把文章业务加入通用 Web 桥，不改变其他页面行为。

| 建议位置／职责 | 复用和边界 |
| --- | --- |
| pages/ArticleEdit.ets | HPTScaffold 页面壳，编辑区与原生媒体工具栏；处理导航返回 |
| view_models/ArticleEdit.ets | 页面会话、标题／正文摘要、校验、上传／保存互斥、成功退出；不保存到手机就冒充后台成功 |
| components/ArticleEditorWeb.ets | 本地文档加载、ready 握手、编辑专用桥、焦点／选区／快照；不在 ArkTS 中解析任意 HTML 布局 |
| api/ArticleEditorApi.ets | 可继承既有 DoctorNetworkApi，复用图片上传并新增文章保存；避免为复用上传跨依赖其他 yzs 模块 |
| services 下的媒体及编辑会话辅助 | 系统媒体选择、临时文件生命周期、图片任务顺序；仅在实际复杂度需要时拆分 |
| resources/rawfile 下 HTML／JS／CSS | 标题输入与正文 contenteditable，限定支持的格式与本页样式，不用截图作为界面资源 |
| MyArticles、文章动态路由及共享 RouterName | 只增加手机上编辑入口与页面注册；其他新建选项不改 |

建议新增 biz_web 的直接依赖以复用 BaseWebContent；FileUtils 等若实际引用，再补对应直接依赖。当前 yzs_article 尚无 biz_web 依赖，不能假定直接可用。文件名为评审建议，实施前按届时分工及代码状态确定；不提前建立用不到的抽象。

### 页面效果与组件复用要求

用户明确要求页面和组件符合当前效果、合理复用现有组件。本页以最新 Figma、保存弹框截图及已确认业务为展示目标；复用通过现有组件的配置和组合完成，不能直接采用与设计不符的默认外观。当前仅核对组件能力，不表述为已运行或视觉验收通过。

| 退出确认框 | HPTDialogUtil | 复用两按钮布局，使用已确认提示和继续编辑／返回回调；通过单次调用配置本页样式 |

| 图文编辑容器 | biz_web/BaseWebContent | 复用加载、controller 与生命周期能力，仅封装本页文档、专用桥和编辑状态 |
| Toast、加载、上传、路由 | HPTToastUtil、既有加载组件、DoctorNetworkApi、dynamicPageRegistry | 沿用本端能力；本页只增加业务绑定，避免重复请求、重复提示和跨功能模块依赖 |

HPTDialogUtil 的默认按钮样式会按索引回退，不能依靠默认值推定黄色／灰色效果，三枚按钮均显式传样式。字号、颜色、圆角、间距优先映射项目已有资源或实例配置；若标题对齐等细节不能由默认标题表达，可通过现有 customMessage 组合本页标题内容，仍复用原弹框容器和按钮布局，无需新增专用 Dialog 组件。

本页动态注册 Builder，不添加 Entry 路由注解。

本页不调用 HPTDialogUtil.settingConfig 或 HPTButton.settingPrimaryConfig 等全局设置来适配局部设计。页面使用到的宽高、留白、状态颜色和点击反馈通过本次实例配置设置，避免影响其他页面。已有 V1 组件保持当前用法，新增业务组件使用 V2，不因本页开发迁移共享组件。

组件拆分以独立职责为准：Web 编辑区需要隔离 controller、桥和文档生命周期，保留局部组件；只有本页使用的弹框配置与简单工具栏先用方法／Builder 组合。第二个实际复用场景出现后再评估公共抽取，不提前新建全局文章编辑框架或重复包裹已有按钮、弹框、导航。

### Web 容器的具体限制

已核对[BaseWebContent](../../../repos/hos_doctor/biz_web/src/main/ets/components/BaseWebContent.ets)：支持本地 Resource、外部 controller、生命周期回调及 protocolMode。NONE 模式会返回空桥对象数组，因此不能仅传自定义 arkJsObject 就声称桥已注入。

建议本页使用 NONE 模式关闭通用业务桥，在 onControllerAttached 中通过页面自有 controller 注册编辑专用对象，配合本地文档 ready 握手。只暴露编辑状态回调等窄接口；原生主动调用文档方法读取快照或插图。沿用 BaseWebContent 的默认 client 与生命周期转发，不同时传入会绕开这些回调的自定义 webClient。注册路径已经编译及设备加载验证，不修改共享 NONE 语义。实际设备验证中已为 BaseWebClient 补充 resource://rawfile/ 的窄范围放行，否则它会拦截本地文档；未知协议仍拦截，并有回归覆盖。未维护第二套通用 Web 基础模块。

### 编辑专用桥与初始化时序

编辑专用桥只面向应用内置文章编辑文档，不复用通用网页业务桥。消息使用明确类型的协议对象，ArkTS 侧定义具名 class／interface，不增加任意函数调用或通用网络入口。

| 交互 | 载荷与处理 |
| --- | --- |
| 文档就绪 | JS 报告协议版本和 ready；仅接受当前 controller、当前本地编辑文档的就绪通知 |
| 初始化 | 原生生成 sessionId，传入初始标题、正文及版本；JS 同一会话只初始化一次，重复 ready 或 onPageEnd 不覆盖用户输入 |
| 编辑状态变化 | 回传 sessionId、递增 revision、焦点字段、composition 状态及正文有效性摘要；不在每次按键回传全文 |
| 读取最终快照 | 原生携带 requestId 获取标题、HTML、有效文字、有效图片数、未完成图片数及 revision；只接收当前请求结果 |
| 媒体命令 | 使用 taskId、anchorId 和会话标识定位预占位节点；成功只替换对应节点，不按当前光标重新插入 |
| 销毁 | 会话失效后拒绝所有旧回调，清理桥对象、事件监听和本页临时文件 |

进入页面后先挂载 Web，再在 controller attached 注册编辑桥；文档 ready 后发初始化，收到初始化完成结果才开放保存和媒体操作。onPageEnd 只作为 ready 状态探测的补偿，不能仅凭加载结束就认定编辑器已可用；不使用固定延时猜测初始化完成。初始化失败提供本页重试，不能把未读到正文当空文章。

读取快照前等待正在进行的输入法组合结束，取到一致快照后再校验并打开保存弹框。快照读取失败、桥调用失败或超时均恢复编辑状态，不发保存请求、不清空内容。弹框期间保留该快照并阻止底层内容继续变化；继续编辑后解除暂时锁定，再次保存重新取快照。

消息和正文使用 JSON 序列化传递；JS 调用的函数名固定，用户文本只作为数据。每个结果同时检查 active session、requestId／taskId 和页面是否已销毁，不能只依据 Promise 已完成就更新 UI。

## 3 编辑文档与输入

正文采用受控 contenteditable，不把文章 HTML 直接当整个应用页面运行。标题用文档内的多行纯文本输入，与正文共享滚动区；顶栏和图片工具栏保留原生，以适配鸿蒙键盘与系统媒体界面。

编辑器 JS 提供清晰的会话方法：初始化内容、获取快照、保存插入锚点、插入／更新图片、报告焦点和内容变化。快照包含标题、规范化 HTML、有效文字摘要、有效图片数和修订号。方法名与字段在实施时定稿，不作为新增后台协议。

- 用户确认的校验使用有效内容：标题非空且最多 30 字；正文有非空白文字或有效图片。空 p／div／br、空格、不换行空格等不计有效正文。
- 标题按已确认的 30 字上限实现，采用用户可见字符计数并兼顾表情组合；输入法 composition 期间不强行截断，提交时再次校验。Q-007 作为技术细化处理，无需另行业务确认。
- 支持插入、删除、选择、复制、剪切、粘贴及图片前后编辑。基础撤销／重做链路在实施验证中检查，不在最新稿之外新增按钮。
- 用 input／composition／selectionchange 等事件维护状态，编辑时不因 ArkTS 状态刷新反复重建 Web 或覆盖 innerHTML，避免光标跳动、候选字丢失和撤销历史被清空。
- 粘贴保留文字、换行、段落以及加粗、链接等已确认基础格式；富格式经 DOM 解析和标签／属性白名单清洗，不用正则代替 HTML 解析。去除脚本、事件处理属性和不支持的外部嵌入；编辑文章中的链接不能带着本页桥跳去其他文档。
- 不在文档里注入 token、用户凭据或完整网络能力。数据以结构化序列化参数传递，不能把用户正文、图片地址直接拼进可执行 JS 字符串。

内容往返保留文字、换行、段落、加粗、链接及图文顺序。粘贴清洗需保留加粗和链接的语义，而非全部转纯文本；不承诺列表、表格、任意 CSS 或其他复杂排版无损，也不新增剪贴板图片上传。旧文章回填只有相关入口进入本轮范围后才纳入实施，当前不为未确认入口提前实现一套详情流程。

### 粘贴规范化、字数与保存快照

允许的最小语义集合为段落容器、换行、加粗、链接及本页已插入图片。粘贴时将 p／div／br 的分段保留，strong／b 归一为加粗；span 中的常见加粗样式可转换为同一语义。链接保留文本和合法的 http／https 地址，编辑时点击不离开当前文档。普通字体、字号、颜色、外边距等外部样式清理后使用本页样式；表格或列表等未纳入的结构只保留可读文字与分段，不保持其复杂排版。

粘贴的外部 HTML 不直接插入可执行 DOM。先在分离文档中解析并清洗脚本、事件属性、外部嵌入及不支持属性，再用受控编辑事务插入。剪贴板位图、外部 HTML 的图片和视频不触发隐式上传；本期图片来自拍照／相册。本页内部已有图片的编辑和序列化保留已登记的远端地址，不根据剪贴板任意地址生成有效图片任务。

内部只保留一份规范化的原始 HTML，序列化时删除占位状态、按钮、选区锚点及其他编辑辅助属性。有效正文使用文字内容去除空白后的结果加已上传图片判断，空 p／div／br 和失败占位不算图片。正文中的用户文字仍通过 DOM 文本节点与序列化处理，不能为了非空检查就删去用户输入的段落。

标题校验以去除首尾空白后的内容判断非空，但不靠视觉省略实现 30 字限制。编辑区采用可见字符边界计数，组合输入期间保留候选内容，composition 结束及粘贴结束后限制超长部分并提示“标题最多输入30字”，不截断表情。优先使用目标 ArkWeb 支持的字素分段能力，最低支持系统上验证可用性；若需兼容分段实现，集中在本地编辑器工具中，不改变后台字段。

新建返回的“是否空白”和保存前的“是否有效”分开判断：新建只要仍有用户输入或未完成图片任务就按有未保存内容处理，不能因为内容暂未满足保存校验而直接退出；删除回到空白则按空白新建退出。已有文章快照差异规则只记录为未来入口复用参考，不在本轮增加旧文章加载流程。

## 4 图片和键盘

### 图片链路

1. 正文编辑时点击相机／相册，先记录当前插入位置和页面会话；点击原生按钮不能把插入点无条件移动到末尾。
2. 调用系统相机或 PhotoViewPicker，仅选择图片。相册按已确认规则设置 maxSelectNumber=9，与 iOS 单次上限对齐。已有 hpt_utils/MediaUtils 封装固定单选，不能直接满足此需求；优先在本页媒体服务配置数量，不顺带修改全局调用方。
3. 把选中的 URI 按既有文件工具复制到本页临时目录，复用 DoctorNetworkApi 的压缩编码与上传。已有上传能力是基类能力，不复用其他 yzs 模块的 ViewModel。
4. 图片任务按选择顺序绑定稳定锚点。选图完成后按选择顺序插入不可编辑的临时图片占位节点，成功后原位换成图片；任务绑定会话和任务 ID，用户删掉占位或离开页面后，迟到回调不再插回正文。失败占位采用本页内的重试／删除操作作为异常细化，不新增独立页面或格式工具栏。
5. 对上传成功的图片保留可访问的远端 URL 和必要尺寸；宽度适配内容区、高度等比，不硬编码拉伸。可以逐张串行上传以控制内存并保持顺序，避免基类按图片格式分组返回时打乱选择顺序。
6. 保存前排除上传中／失败占位及临时 URI，不能把 file、blob 或 base64 临时内容作为已完成的后台文章提交；有未完成上传时提示处理完再保存。

取消相机／相册或未获得权限时保留正文和选区。上传失败支持重试或删除，不清空整篇文章；请求回调绑定当前页面生命周期。图片只通过现有上传结果形成远端资源地址，不新增上传服务器。

复用依据：[DoctorNetworkApi.upload](../../../repos/hos_doctor/biz_middle_extension/src/main/ets/api/DoctorNetworkApi.ets)第 83 行起；[MediaUtils](../../../repos/hos_doctor/hpt_utils/src/main/ets/utils/MediaUtils.ets)第 32、110 行起。基类支持的图片编码规则是工程现状，不等于产品已确认所有文件格式或大小上限，具体输入范围在实施前核对。

### 上传任务、失败恢复与文件清理

每次选择是一个批次，但每张图片拥有独立 taskId 和占位。按选择顺序逐张上传，每次调用基类上传单张文件，成功与原位置绑定，不依赖多格式分组后的响应排列。取消选图、结果为空时不创建任务；打开选择器前记住的 Range 如果在返回时已失效，使用已保留的正文锚点恢复，不把图片静默追加到文章末尾。

上传成功同时满足上传状态码成功、返回列表存在、图片 ID 与 oss_obj 有效。相对对象路径通过当前环境配置的图片／文件资源基址形成 URL；若返回合法完整 URL 则不再次拼接，不写死生产域名。临时文件位于当前会话缓存目录，文件读写句柄和解码对象在 finally 中释放。保留上传失败文件供本页重试，图片删除或页面真正销毁时清理，不能在系统相册返回前误删。

上传失败只标记对应占位并允许重试／删除，成功图片与正文保留；在有上传中或失败任务时，保存动作提示先完成上传或删除失败图片，不能过滤失败图片后静默保存残缺文章。用户删除任务后，未发起任务从队列移除，在途结果到达时丢弃；选择返回放弃页面时取消本页请求并让会话失效。取消客户端请求不代表能撤回已上传的服务器文件，本期不新增远端删除接口，也不擅自改变现有上传回收策略。

### 键盘和工具栏

文章编辑器的原生外层容器单独消费点击，避免点击正文时触发首页外层的 `clearFocus()`。Web 仍自行处理光标和选区，不增加重复聚焦或主动唤起键盘；正文内重复点击应保持键盘显示。此处理只应用于本地文章编辑器，不修改首页其他页面的点击清焦点行为。

布局为固定原生导航、可伸缩编辑内容区、原生两图标工具栏。建议由 ArkUI 的 RESIZE 模式负责缩小可用区域，Web 随容器重排；不要同时缩容器、减键盘高度和移动工具栏，造成重复避让。键盘高度用于判定可见性时，应与正文焦点共同决定工具栏显示。[官方 Web 软键盘文档](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/web/web-docking-softkeyboard.md#设置软键盘避让模式)

正文获焦且软键盘可见时显示工具栏；标题获焦、键盘收起时隐藏。长文滚动时确保光标在工具栏上方，标题随文档滚出、导航固定。页面进入时记录原有避让设置，页面失去可见性时恢复、重新可见时再设置；真正销毁时释放监听。从系统相机／相册返回不重载已有文档，不把普通前后台切换当会话销毁。软键盘、外接键盘、中文候选栏切换及系统返回先收键盘的实际事件顺序必须运行验证。

系统键盘使用本机输入法。相机／相册只显示最新稿的两枚图标，保留合适点击区域与无障碍名称，不照搬两端图标＋文字的旧栏。图标素材已导入：拍照使用 app.media.camera_key，相册使用 app.media.photo_lib_key，均为原始 24×24 SVG；具体文件链接见产品需求。不得重绘或用系统符号替代。工具栏高度已由用户明确为48vp，按钮高度同步48vp，图标保持24×24；其余边距按下表区分现值与设计依据。

## 5 后台保存与数据兼容

### 已确认的暂存草稿

接口为 `article/create_doctor_article`，暂存草稿传 `is_send=0`。只有后台成功后提示“保存成功”，随后退出编辑页。手机本地状态不是业务草稿保存成功的依据。

新建入口的医生文章 ID 和系统文章 ID 为0；已有文章入口保留传入的两个原ID。保存请求的标题、内容、医生名称沿用既有文章接口；既有网络鉴权、环境与表单处理由项目网络层承担，不在本地 HTML 内发请求。

| 参数 | 当前依据／本页处理 |
| --- | --- |
| doctor_article_id、system_article_id | 两端保存接口已有；新建为0，有效已有文章保留四字段参数中的两个原ID |
| title | 已确认非空、最多 30 字；提交前以最终快照再校验 |
| content | HTML 正文；以统一内部表示维护，传输时只做接口需要的一次编码 |
| is_send | 草稿 0、发布 1 均已确认；两者使用同一创建接口 |
| doctor_name | 两端传当前医生名称，鸿蒙使用现有用户状态来源 |
| article_source、article_url 等 | Android 接口有默认值，但不能据字段存在杜撰鸿蒙业务取值；本轮基线参照 iOS 手机新建省略未使用的可选字段，不猜造来源值；服务端差异在联调核对 |

### 表单编码与成功判定

已核对 PostForm：普通对象经 FormEncoder 形成表单，属于传输编码，不等于 HTML 实体编码。方案基线为原始 HTML 快照交给 PostForm，不预先 encodeURIComponent，也不直接照抄 Android 的 htmlEncode。iOS 编辑页此处同样提交 getHTML 结果，但这不足以证明后台所有兼容路径；实施联调需核对特殊字符、换行、链接与图片保存后的回读结果。若实测需要 HTML 实体编码，仅在 ArticleEditorApi 的 content 编解码边界集中适配，禁止同时在编辑器和网络层重复处理。

| 请求 | 成功条件 | 不可误用的判断 |
| --- | --- | --- |
| 创建草稿／发布 | 返回存在且 String(status) 等于 SuccessStatus 当前值 1 | 不能仅检查返回值非空；is_send=0 不是响应状态 |
| 图片上传 | 返回存在且 String(status) 等于 GapiSuccessStatus 当前值 00000，并且图片结果有效 | 不能套用创建接口的成功码，也不能只取列表第一个字符串当上传成功 |

默认请求层可能返回 undefined，也可能在网络错误分支返回非空失败对象，因此页面必须显式检查接口对应成功码。编辑保存请求使用现有 request 的 disableAutoDecideRes=true 获取普通失败对象，由本页统一提示一次并保留内容；此选项不绕过默认鉴权与登录失效处理，认证失效返回 undefined 时不再重复弹登录或错误 Toast。上传基类当前也使用该选项，图片错误由本页任务状态处理。桥错误在本页提示，不发后台请求。保存成功使用已确认的固定文案，不能直接拿任意非空 msg 当成功提示。

证据：[PostForm 与请求处理](../../../repos/hos_doctor/hpt_network/src/main/ets/HPTNetwork.ts)、[响应码定义](../../../repos/hos_doctor/hpt_network/src/main/ets/model/Response.ts)、[默认请求拦截器](../../../repos/hos_doctor/entry/src/main/ets/common/interceptor/Request.ets)、[上传结果归一](../../../repos/hos_doctor/hpt_network/src/main/ets/interceptor/UploadInterceptor.ets)。均为当前源码证据，未进行服务端联调。

### 保存状态与返回

保存弹框 UI 已补齐，使用原生圆角面板，标题为“是否发布并显示在我的医生主页？”，三个按钮纵向排列，依次为黄色直接发布、灰色继续编辑、灰色暂存草稿，参照[用户截图](sources/保存发布弹框-20261030.png)。已核对 HPTDialogUtil 原生支持三按钮纵向布局，直接使用 buttons、逐按钮 style 与单次 config 适配；标题如需自定义对齐，使用其 customMessage 内容组合。保持既有弹框容器与按钮实现，不新建重复 Dialog 组件、不修改全局默认样式，也不把整张截图当界面资源。

推荐页面状态分为初始化、编辑中、媒体选择／上传中、读取快照、保存中。顶部保存先取得最终快照并校验，再弹三选项；继续编辑不发请求。保存中防止再次提交，成功只退出一次，失败恢复编辑且保留内容。超时不自动重复创建文章。

成功返回原来的我的患教文章列表，复用其 onShown 静默刷新，避免同时添加全局刷新事件而重复加载。直接发布流程已确认：请求 article/create_doctor_article，is_send=1，后台成功后提示“发布成功”、退出编辑页并刷新列表；失败时保留内容的安排沿页面异常处理方案，不提前提示成功。Q-005 已关闭。

返回按用户新规则独立处理：空白新建或已有文章未改动直接退出；新建已输入内容或已有文章内容修改时显示“当前内容尚未保存，是否返回？”及“继续编辑／返回”按钮。继续编辑关闭弹框并保留内容；返回放弃本次未保存内容并退出，不调用文章保存接口，也不改变后台原文章的状态。取消此前“保存后退出即存草稿”的建议；暂存草稿仍只通过顶部保存三选项进入。空白新建直接退出已确认，Q-004 关闭。

内容改动建议以初始化完成后的标题和规范化正文快照作比较，焦点、选区及滚动不算改动；文字、图片的实际增删改应能触发判断。页面保留新建标识：新建按当前标题／正文是否已有输入判断，空白直接退出；已有文章按与进入时的内容快照是否有差异判断。

所有返回方式应汇入同一退出判断；HPTScaffold 已有导航返回回调和 NavDestination.onBackPressed 通路，需在实际 Router／NavPathStack 两种承载下核对。空白新建、修改后还原、保存失败、弹框取消等情况按确认后的规则处理，不仅拦截左上箭头。

### 页面状态与并发约束

| 当前状态／事件 | 处理与下一状态 |
| --- | --- |
| 初始化未完成 | 保存和媒体动作不可发请求，返回仍可退出；失败提供本页重试，不把加载失败当成功空文档 |
| 可编辑时打开相机／相册 | 只允许一个选择器，保留选区；取消后返回编辑，不创建占位 |
| 图片上传中 | 正文仍可编辑，上传结果按 taskId 原位回填；有未完成或失败图片时不提交文章 |
| 点击保存 | 防重复进入快照读取；组合输入结束后读取快照，校验通过才展示三选项 |
| 保存框选择继续编辑或取消弹框 | 不发网络请求，回到编辑中，保留正文及选区 |
| 保存框选择草稿／发布 | 锁定同一提交快照与提交动作，只发一次请求；等待期间不再发保存或放弃返回 |
| 后台失败／超时 | 恢复编辑，保留正文和已成功上传图片；不自动重试创建，不提示保存或发布成功 |
| 后台成功 | 草稿提示保存成功、发布提示发布成功；标记本页提交已完成后只退出一次，避免再次触发未保存弹框 |
| 点击返回 | 先取得可靠的当前编辑摘要；空白新建直接退出，有内容则按已确认提示确认；读取失败留页重试，不猜测为空 |
| 放弃返回／页面销毁 | 会话失效，取消本页请求、清理桥与媒体监听、删除本页临时文件；迟到回调不得导航或插图 |
