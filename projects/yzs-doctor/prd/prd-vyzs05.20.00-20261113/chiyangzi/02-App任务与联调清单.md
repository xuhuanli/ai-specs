## 三端实现要点

- 开通状态、患者关联、诊次存入状态、开关状态分别读取和处理，不能用某个本地访问标记替代其他业务结论。
- 来源上下文包括入口类型、医生、就诊人及来源订单；选择集合与预览对象分开，返回时按同一任务恢复。是否跨进程保存由 Q-006 决定。
- 待存／已存 Tab 与二级详情采用 Figma；详情中明确选择同步主列表。小程序返回先展示确认框，点击「我已开通」才核查开通结果并决定是否继续存入。
- 提交结果分为处理中、全部成功、部分成功、明确失败、结果未知。可否异步及状态契约由 DEP-003 决定，不把演示中的固定延时当作真实处理时长。
- 开关即时保存与首次／重新关联提交分别处理；连续点击、请求乱序及失败时的最终展示需与服务端一致。缓存和乐观更新方式在本端方案中决定。
- UI 与交互细节见设计对照；Android 的颜色 token 与字重组件按项目 UI 技能使用。三端只共享业务结果，不共享原型代码或 Figma 生成的 React 代码。
