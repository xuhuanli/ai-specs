# 多端消息跳转需求示例

以下为虚构教学示例，演示如何把一个功能写成开发和测试可使用的需求。角色、规则、文案及决定均为示例设定，可按真实材料替换。

## 1 功能与范围

| 项目 | 示例内容 |
| --- | --- |
| 功能 | 从订单消息进入订单详情 |
| 文档状态 | 示例草稿 |
| 适用端 | iOS、Android、鸿蒙 |
| 目标 | 用户点击本人订单的消息后，能够看到对应订单的最新详情 |
| 本次包含 | 正常跳转、缺少目标、无权访问、登录过期、网络异常及重复点击 |
| 本次不包含 | 推送接收、未读数、消息已读状态、订单编辑及订单状态流转 |
| 相邻行为 | 本示例不定义上述范围外功能的行为；真实开发时应记录其保留规则 |

## 2 示例业务决定

真实文档应把下表替换为可定位的原始材料、设计或人工确认记录。

| 决定编号 | 示例设定 |
| --- | --- |
| D-001 | 只有登录用户本人有权访问的订单才能展示详情，由服务端校验访问资格 |
| D-002 | 缺少目标信息时停留消息列表，提示“暂时无法打开该订单” |
| D-003 | 订单不存在或无权访问时显示相同提示“订单不存在或暂不可访问”，不展示订单信息 |
| D-004 | 点击时登录已过期，进入登录流程；登录成功或取消后回到消息列表，由用户再次点击 |
| D-005 | 目标解析和详情请求进行期间的重复点击不再打开新页面 |
| D-006 | 网络失败时保留消息列表，提示“网络异常，请稍后重试”；用户可再次点击 |

## 3 功能需求

### REQ-001 打开允许访问的订单

- 来源：D-001、D-005。
- 角色：已登录用户。
- 前置条件：消息携带完整的目标信息，订单存在，用户具有访问资格。
- 触发：用户点击消息卡片。
- 规则 BR-001：依据该消息的目标信息打开对应订单，展示服务端返回的最新详情。
- 规则 BR-002：服务端校验订单访问资格；用户不能通过替换目标信息读取他人订单。
- 规则 BR-003：同一打开流程进行期间的重复点击只产生一次页面打开；流程完成或失败后恢复可操作状态。
- 成功结果：展示对应订单详情；返回后回到来源消息列表。
- 关联验收：AC-001、AC-006、AC-007。

### REQ-002 处理缺少目标和不可访问的订单

- 来源：D-002、D-003。
- 规则 BR-004：缺少必要目标信息时保留消息列表，展示 D-002 文案。
- 规则 BR-005：订单不存在或无权访问时保留消息列表，展示 D-003 文案，不展示订单详情字段。
- 恢复：用户可以继续操作其他消息。
- 关联验收：AC-002、AC-003。

### REQ-003 处理登录过期和网络失败

- 来源：D-004、D-006。
- 规则 BR-006：登录过期时进入登录流程；登录成功或取消后回到来源消息列表，结束本次打开流程。
- 规则 BR-007：网络失败时展示 D-006 文案，结束本次打开流程并允许再次点击。
- 关联验收：AC-004、AC-005。

## 4 三端行为与技术依赖

| 需求编号 | 统一目标 | iOS 当前情况 | Android 当前情况 | 鸿蒙当前情况 | 允许差异 |
| --- | --- | --- | --- | --- | --- |
| REQ-001 | 展示对应订单，校验资格，避免重复打开 | 未核对 | 未核对 | 未核对 | 系统返回手势可按平台约定；返回目的地一致 |
| REQ-002 | 失败提示及停留位置一致，无订单信息泄露 | 未核对 | 未核对 | 未核对 | 提示组件形式由设计确认 |
| REQ-003 | 登录后返回位置及网络恢复行为一致 | 未核对 | 未核对 | 未核对 | 登录界面采用各端已有组件 |

| 依赖编号 | 所需约定 | 待确认内容 | 阻塞范围 |
| --- | --- | --- | --- |
| DEP-001 | 消息目标信息解析 | 消息类型、字段、空值和历史格式 | 三端目标解析实现与接口联调 |
| DEP-002 | 订单查询与授权 | 已有接口、业务状态、错误含义及响应结构 | 详情查询、访问资格和错误映射 |
| DEP-003 | 登录和返回 | 登录组件返回约定、账号切换时的列表刷新 | 登录过期及账号切换分支 |

## 5 验收条件

采用 Given 表示前置条件、When 表示操作、Then 表示可观察结果。以下每项均适用于三端。

| 编号 | 关联需求 | Given | When | Then |
| --- | --- | --- | --- | --- |
| AC-001 | REQ-001 | 用户已登录，目标订单存在且允许访问 | 点击订单消息 | 展示该消息对应订单的最新详情；返回后回到来源列表 |
| AC-002 | REQ-002 | 消息缺少必要目标信息 | 点击消息 | 保留列表，提示“暂时无法打开该订单”，可继续操作其他消息 |
| AC-003 | REQ-002 | 目标订单不存在或无权访问，分别准备两组数据 | 点击消息 | 两组均保留列表，提示“订单不存在或暂不可访问”，不展示订单详情字段 |
| AC-004 | REQ-003 | 点击前登录已过期 | 点击消息后，分别完成或取消登录 | 先进入登录流程；成功或取消后均回到列表，由用户再次点击 |
| AC-005 | REQ-003 | 目标有效且详情请求因网络失败 | 点击消息 | 保留列表，提示“网络异常，请稍后重试”；网络恢复后再次点击可正常打开 |
| AC-006 | REQ-001 | 人为延迟本次详情请求，使打开流程保持进行中 | 首次点击后再次点击同一消息 | 页面仅打开一次；失败后再次点击仍可发起新的打开流程 |
| AC-007 | REQ-001 | 登录用户尝试读取其无权访问的订单 | 通过接口请求该订单详情 | 服务端拒绝访问，响应不返回受保护的订单详情字段 |
