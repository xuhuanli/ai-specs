## 3 页面来源规则

`followup_plan_view` 的 `event_tag` 只有“开方记录、开方详情”两种已确认业务来源，由直接打开随访计划弹窗的按钮所在页面传入。例如开方记录 → 开方详情 → 随访计划，记录“开方详情”。上报统一放在随访计划内的成功展示节点。

`followup_feedback_view` 的 `event_tag` 区分以下七类来源。名称表达业务含义，实际上传编码由后台 API 确定。

| 来源 | 入口 | 传递规则 |
| --- | --- | --- |
| 系统通知 | 反馈相关系统 Push | 经过订单详情等中间页面仍保留系统通知来源 |
| 消息 | 消息中心反馈相关条目 | 沿本次消息跳转链路传递，不在中途覆盖 |
| 待办 | 首页待办、待办助手中的反馈相关条目 | 经过订单详情后打开完整反馈，仍保留待办来源；待办字段待协议 |
| 咨询 | 咨询会话中已确认的反馈相关卡片 | 沿本次咨询链路传递，其他卡片不自动纳入 |
| 开方页 | 开方页手动打开完整反馈 | 无引导来源的手动打开，按直接入口页面记录 |
| 开方记录 | 开方记录手动直接打开完整反馈 | 若先进入开方详情再手动打开，则记录开方详情 |
| 开方详情 | 开方详情手动打开完整反馈 | 仅无通知、消息、待办、咨询引导来源时取此值 |

引导来源优先沿本次进入链路保留，不因中间经过开方详情或再次点击查看按钮而覆盖。新的独立手动打开按当前直接入口取值，不能沿用旧链路来源。入口点击、中间页、通知接收和已读标记不单独算反馈查看。

## 5 本次新增 UI 需求

关联 SAN-REQ-005、SAN-AC-017、018。随访计划弹窗顶部“随访重点”和完整反馈弹窗顶部“随访小结”取消展开／收起，正文全部平铺展示，长内容随页面滚动。

完整反馈在随访小结卡片底部新增“复制随访小结”区域，复制当前小结正文，成功后提示“复制成功”。该入口与原有舌象分析、问卷答案复制共同计入 `followup_summary_copy`。复制失败不报成功事件。用户本次确认取代此前“不新增小结复制”的规则。

设计来源：[用户提供的随访弹窗UI调整截图](../sources/随访弹窗UI调整-20261022.png)。2026-10-23 UI已由`8fd3ad334`实施提交；构建、随访UI真机结果及验证边界见[AI测试记录第8节](04-AI测试用例.md#8-鸿蒙随访-ui-验证收尾2026-10-23)。四项上报仍未接入新API，本地复制成功不代表后台消费记录已上报。
