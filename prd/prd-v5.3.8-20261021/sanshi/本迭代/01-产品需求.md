## 2 预览处方共同业务规则

医生从当前开方进入预览，核对患者、药方、诊后设置和费用，再选择返回继续编辑，或生成并发送处方。预览所呈现的信息必须与本次开方一致，不能把最近一次订单或其他处方的数据带入当前预览。

1. 点击预览本身不落单、不发送处方。正式生成仍遵守当前业务校验、风险确认、签名和角色权限等原有处理。
2. 返回开方页保留原编辑数据；修改后重新预览，应展示修改后的内容和对应计算结果。
3. 不因新版设计仅展示单个剂型或部分字段，而省略原有支持的剂型、条件内容、说明和交互。
4. 页面中示例姓名、电话、药材、金额、剂数和天数仅用于表达 UI，不作为固定值或默认业务规则。
5. 复用订单详情的展示样式和适用交互；订单状态、支付、履约、诊后结果和操作条件不能因复用而进入生成前预览。
6. 药方编号仅在最后开方成功后产生。Android、鸿蒙预览均隐藏编号行和复制入口，不展示占位编号，不借用复诊来源订单号，也不为预览提前生成订单。
7. 医师责任险按现有订单详情逻辑展示，复用固定文案、样式和条款跳转，不依赖新增保险状态字段或接口。

## 3 SAN-REQ-001 Android 预览处方 UI 改造

保留现有预览入口、开方缓存和预览数据来源，将现有页面改为最新 Figma 的顶部、卡片、字体、间距、背景、费用区与底部操作布局。订单详情中可直接使用的组件优先复用；适当复制适用布局也是本次允许的实现方式，但需按预览数据重新绑定。

当前 Android 预览已有的患者和病历信息、图片查看、药库介绍、协定方、剂型与药材展示、颗粒剂显示切换、包装和拆包说明、备注和医嘱、诊后设置、优惠与费用明细、金额明细隐藏配置、医助审核分支和生成回调均属于需要保留的范围。条件字段仅在原有适用场景出现，不要求所有字段同时展示。

UI 改造不能把生成动作换成订单详情中的支付、取消、物流或回访动作；也不能通过复制订单详情页面直接触发其订单查询、状态判断或其他副作用。

复用患者卡片时隐藏药方编号及复制入口；现有预览中的保险隐藏处理按本次确认调整为与订单详情一致的固定展示和条款跳转。

## 4 SAN-REQ-002 鸿蒙新增预览处方

### 4.1 开方入口

在当前普通开方页增加“预览处方”按钮，位置、与生成按钮的组合及用户操作参照 Android 当前开方页。原有直接生成入口继续保留。涉及的剂型随该开方入口现有支持范围覆盖，不把本需求扩展成照片开方独立流程或经方验方其他入口的整体改造。

点击预览后，依据当前开方内容和本次预览计算结果进入新页面；遇到原有必填或药方校验问题，沿用现有校验反馈。风险提示与签名的时序对齐 Android：在进入预览前完成适用的辅料、胶量、用药风险确认及签名，再展示预览。进入预览不得直接沿用会继续落单的生成完成回调。

### 4.2 新页面

在订单模块 `yzs_order` 内新增独立预览页，通过公共动态路由进入，共用该模块内适用的患者、药方、诊后设置、保险与费用展示。开方模块负责组装当前开方数据和预览结果，订单模块负责页面呈现与交互，不直接依赖开方模块内部的业务管理对象。

数据按生成前开方信息重新构造，不要求先创建订单再预览。编号行和复制入口隐藏，保险按现有订单详情固定展示并打开现有条款页面。展示组件按实际需要在订单模块内提取复用，不为本需求整体迁移到其他模块。

顶部只展示“预览处方”，不展示待付款、已签收、已反馈等订单或诊后状态标题。底部只有一个生成操作；普通医生显示“生成处方并发送给患者”，受限医助沿用给医生审核的角色规则。订单详情中的其他底部按钮和更多菜单不进入预览。

合计与明细按当前设计及鸿蒙订单详情展示，保留对应展开收起操作；本期不额外引入 Android 的“隐藏金额明细”配置判断。这是用户确认的平台差异，Android 原有配置继续保留。

### 4.3 生成与返回

点击预览底部生成操作后，将生成事件回传开方模块，继续原有患者信息、颗粒剂授权、屏蔽检查、提交与角色分流，不在点击时立即关闭预览。已在进入预览前完成的同一次风险确认不因回传而重复触发。

取消确认或提交失败时的页面位置对齐 Android，保留预览；需要修改患者资料或药方时返回编辑。生成成功后清理预览，再沿用原成功页或咨询返回流程，不能只替换或退出新增的预览页而留下错误的导航栈。

主动返回开方页继续编辑不清空开方信息，也不提交。再次进入预览时，展示最新数据，不重复使用旧编辑状态的金额或内容。

编号与保险规则已明确，SAN-Q-001、002 已关闭，不再作为预览开发的外部依赖。

三项现有预览请求参数差异仅作为开发阶段备注，不阻塞当前方案确认。开发涉及相关参数时先找用户确认，再更新处理逻辑及文档，不自动按 Android 补传；具体字段见技术方案 SAN-NOTE-001。

## 5 SAN-REQ-003 鸿蒙随访待办跳转

本项只适用于用户后续指定的待办类型。后台类型、额外参数名、参数位置和目标随访标识尚未提供，不与现有 `FOLLOW_UP`、其他待办协议或现有路由字段直接划等号。

| 场景 | 目标行为 |
| --- | --- |
| 指定待办携带有效的约定额外参数 | 先进入对应订单详情，再 push 参数对应的反馈详情；关闭反馈详情后回到该订单详情 |
| 指定待办不携带约定的额外参数 | 只进入对应订单详情，不自动打开随访详情 |
| 额外参数为空、类型异常或不能定位对应反馈 | 按无有效参数兜底，保留对应订单详情，不自动打开错误的反馈 |
| 其他待办 | 保留原有跳转和待办处理规则 |
| 后台不再返回的待办类型 | 客户端无额外开发，不新增过滤、删除或状态迁移逻辑 |

用户已确认上述目标与兜底处理。具体待办类型、字段位置与类型、有效性校验依据、反馈标识及路由所需上下文仍待协议补齐，不猜测字段。保留当前待办点击标记、完成或列表更新行为，不因增加跳转而统一改变任务状态。

### 6.2 实际查看反馈的来源

已确认需要区分五类来源，名称在这里表达业务含义；上传字段名、类型和枚举值由后台确认。

| 来源 | APP 对应入口 | 处理规则 |
| --- | --- | --- |
| 系统通知 | 系统通知栏中的反馈相关 Push 通知 | 将来源随有效通知的跳转链路传到完整反馈页；收到通知本身不计入查看 |
| 消息 | 消息中心的反馈相关消息条目 | 点击和已读标记不单独作为本期埋点；实际反馈展示后携带消息来源记录 |
| 待办 | 首页待办卡片、待办助手中反馈相关条目 | 沿待办到订单详情、再到完整反馈的链路传递来源，具体类型仍待后台确认 |
| 手动点击 | 医生主动从开方记录等入口逐步进入订单详情，再查看完整反馈 | 标记自主进入，与推送、消息中心等引导链路区分 |
| 咨询 | 咨询会话中的反馈相关卡片 | 只针对已确认的反馈卡片类型，实际反馈展示后携带咨询来源记录 |

来源沿本次进入反馈的链路传到最终页面。由系统推送、消息中心、待办或咨询引导的链路保留相应来源；医生自主逐步进入的链路记录手动点击来源。中间经过订单详情或按钮操作，不另发查看事件，也不把所有链路统一覆盖成手动来源。新的独立手动打开不能沿用先前通知链路的来源。

### 6.4 后台记录与交付边界

原文 B01 至 B06 的订单随访配置、计划生成结果、提醒时间调整、消息发送、有效反馈形成及医生通知发送，优先由后台根据业务事实或日志记录，不纳入本人四项行为埋点。E03 患者打开反馈单、E04 患者首次作答属于患者端，不由鸿蒙医生端代做。

客户端四项行为按新增 API 对接，不再把旧访问或已读记录作为省略行为上报的替代方案；后台是否复用内部记录由其新协议和实现处理。API 地址、事件名、具体参数、业务成功码、请求幂等和失败处理等传输细节仍待用户下周提供后补充，不改变本节已确认的业务计数规则。

埋点不得改变原有页面、分享、复制、跳转和生成结果，不新增复制功能或扩大至其他端。埋点开发和联调均后置，本轮仅同步规则；预览两项的已确认要求保持不变。

| SAN-AC-007 | SAN-REQ-003 | 指定鸿蒙待办包含已确认的额外参数 | 对应订单详情先入栈，对应随访详情随后 push，关闭后回到同一订单，不错配数据 |
| SAN-AC-008 | SAN-REQ-003 | 同类待办无额外参数，参数为空、类型异常或不能定位反馈；另对比其他待办 | 无有效参数时仅保留对应订单详情，不自动打开错误反馈；其他待办行为不变 |
| SAN-AC-009 | SAN-REQ-004 | 四项埋点的上传协议与统计口径确认后执行对应行为 | 后台收到与约定一致的事件、参数及频次；不直接套用历史 AI 事件字段，不影响业务结果 |
| SAN-AC-010 | SAN-REQ-004；E01 | 打开随访计划并成功展示；随后刷新、重建及关闭重进，对比加载失败 | 同次打开成功展示只记一次，刷新或重建不多记，关闭重进成功后再记一次；仅入口点击或失败不记 |
| SAN-AC-011 | SAN-REQ-004；E02 | 执行“微信发送给患者”，分别覆盖调用并跳转成功、失败或未跳转 | 只在微信调用成功且已跳转时，每次真实成功操作记一次；不以版本同步或函数正常返回代替，不要求患者最终发送或收到 |
| SAN-AC-012 | SAN-REQ-004；E05/E06 合并 | 从五类来源经不同中间页面进入完整反馈，刷新及重新打开 | 只在最终反馈页成功展示记录，并保留准确来源；同次打开只记一次，重新打开成功再记；无独立点击事件，无旧来源串入新的手动链路 |
| SAN-AC-013 | SAN-REQ-004；E07 | 分别使用完整反馈页已有舌象分析复制和问卷答案复制，多次主动复制并覆盖失败 | 保留原按钮和内容，每次成功复制记一次；同次操作重复回调不多记，失败不记；不新增小结复制入口 |
| SAN-AC-014 | SAN-REQ-002 | 鸿蒙从开方进入预览，覆盖适用的辅料、胶量、用药风险及签名场景 | 按 Android 现有时序在进入预览前完成适用确认；取消或返回修改不自动生成，预览底部生成不重复触发同一次已确认内容 |
| SAN-AC-015 | SAN-REQ-002 | 在预览点击生成，分别取消确认、提交失败、返回修改及生成成功 | 对齐 Android：取消或失败保留预览，需要修改时返回编辑；成功清理预览，再按原开方入口完成成功页或咨询返回，无错误栈残留 |
| SAN-AC-016 | SAN-REQ-002 | 查看鸿蒙预览合计与费用明细，展开并收起 | 与当前设计及鸿蒙订单详情一致，使用本次预览响应；不额外引入 Android 的隐藏金额明细配置判断 |
