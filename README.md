# 三端同步开发工作区

本目录用于组织 iOS、Android、鸿蒙医生端的同步开发。三个代码项目分别来自独立的 GitLab 仓库，在各自目录内开发、验证和提交；根目录使用独立的本地 Git 仓库记录需求资料与跨端协作文档的变更。

工作区根目录本身及三个代码仓库之外的全部文件和目录均仅在本地维护，不上传任何远程，包括根 README、AGENTS.md、通用模板、专题文档和版本需求资料。根目录文档通过本地 commit 记录历史，不配置远端、不执行 push；三个子仓库按各自约定独立管理代码提交与上传。

## 版本需求文档

- 后续各版本的需求相关文档集中放在 `prd/` 下，首次创建路径为 `prd/prd-vxxx-YYYYMMDD/`，不在工作区根目录直接新建版本目录。
- `xxx` 替换为实际确认的版本标识，日期采用 `YYYYMMDD`。例如 `prd/prd-vxxx-20261021` 展示日期格式，其中 `xxx` 仍为版本占位符。
- 确定实际版本后再创建目录，不从某一端当前分支名推定三端版本。日期取该版本目录首次创建的日期；同一版本的后续补充继续维护原目录并记录变更，不随修改日期重复创建。在 [prd/README.md](prd/README.md) 登记版本目录索引。
- 版本内分别维护产品需求、技术方案、开发任务、AI 测试用例、人工测试验收五份文档，并按需保存来源与索引；小需求可以裁剪章节和篇幅，保留各份文档职责。
- 产品与设计确认三端共同业务逻辑、交互及业务验收标准；各端开发维护技术方案和任务；测试维护两份测试资料，AI 辅助生成和执行具备条件的用例。配套文档通过需求编号和业务验收编号关联同一份已确认需求。
- 这些版本需求资料仅在本地维护，由根目录文档仓库记录本地提交历史；不上传、不纳入三个代码仓库的 commit，不复制进三端仓库以参与提交。
- 三端共同需求和对齐结论以 `prd/` 下对应版本资料为入口。仓库自有的架构、模块说明和其他维护文档仍按各项目规范更新；版本需求资料的存放位置以本节约定为准。

## 三端同步开发记录

三端项目的目录定位、开发规范、Git 约定及已发现的来源差异见[三端开发说明](三端开发说明.md)。该说明与其他根目录资料一样，仅本地维护。

长期有效的三端协作约定记录在本 README；内容增多时可在工作区根目录新建专题文档，并在这里添加链接。具体版本的需求、差异和开发进度记录在对应的 `prd/prd-vxxx-YYYYMMDD/` 内。

每个版本按实际范围记录：

- 已确认的共同业务规则、各端适用范围和允许的平台差异。
- 各端当前行为与目标行为，来源冲突及最终决定。
- 分别使用的仓库、分支、关键提交、受影响文件和依赖。
- 各端实现、验证、提交及推送状态，区分静态检查和实际运行验证。
- 需求变化及其对其他端、接口和测试的影响。

产品需求文档确认阶段统一三端的业务流程、业务规则、状态含义和业务验收口径，形成共同的业务逻辑基线。研发分别按该基线实现，工程架构、技术实现、代码风格、分支、提交和验证继续遵循各端自己的约定，不要求三端采用相同代码组织或技术方案。涉及跨端行为时分别核对调用链；业务差异先在需求确认中明确目标，再修改受影响端。

## Git 与提交边界

- 根目录是独立的本地文档仓库，通过本地 commit 记录根 README、AGENTS.md、模板、专题文档及版本需求等资料的变更，不配置远端，不向 GitLab 或任何其他远程推送。
- 根目录 `.gitignore` 排除 `ios_doctor/`、`android_doctor/`、`hos_doctor/` 和系统文件；三个代码项目不作为根仓库内容、子模块或 gitlink 提交。
- 三个项目分别拥有自己的 `.git`、分支、远端和提交历史。所有 Git 操作明确目标仓库，使用对应目录作为工作目录，或用 `git -C <目录>` 指定。
- 三端代码需要提交时，在各自项目内分别检查、暂存和 commit，只纳入该项目本次任务相关的改动，分别遵循其提交规范；不把根目录资料复制进子仓库参与上传。
- 根目录文档的本地版本记录授权不延伸到三端代码仓库。三端的 commit、push、amend 等操作按用户明确授权和目标仓库规范执行。
- 提交和推送状态分别报告，各端完成情况分别记录。
